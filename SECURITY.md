# Security Policy — LinguaNova

## Versiones soportadas

Mientras LinguaNova no tenga una primera versión pública estable, los informes deben dirigirse a la rama de desarrollo activa.

Después de la primera publicación, esta tabla deberá actualizarse por versión.

## Cómo informar una vulnerabilidad

Preferencia:

1. usa **GitHub Security Advisories / Private vulnerability reporting** del repositorio LinguaNova cuando esté habilitado;
2. no publiques claves API, tokens, archivos privados, rutas personales ni exploits sensibles en un Issue público;
3. si el informe privado todavía no está habilitado, abre un Issue mínimo solicitando un canal privado, sin incluir el secreto o detalle explotable.

## Qué incluir

- versión o commit;
- sistema operativo;
- pasos mínimos para reproducir;
- impacto;
- registros pertinentes, eliminando datos sensibles.

## Dependencias

Los problemas en dependencias externas también deben informarse al proyecto correspondiente cuando proceda.

## No garantía

Este proceso de reporte no crea una garantía adicional sobre el software.
